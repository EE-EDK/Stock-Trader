Alpha Vantage

News sentiment from Alpha Vantage (free tier has a daily call limit). More articles and tickers use more API calls but can improve signal quality.

Turn on to add Alpha Vantage news sentiment to the pipeline. Off = no Alpha Vantage calls; signals rely on other sources only.
How many top tickers (by velocity/activity) to run through Alpha Vantage. Higher = more API usage and potentially richer sentiment; lower = fewer calls.

Yahoo Finance

Yahoo Finance data is free and unlimited. It feeds price history, fundamentals, and analyst ratings used in signals and the dashboard.

Master switch for Yahoo Finance. Disable to skip all YFinance collection (pipeline will have less price and fundamental data).
When on, fetches fundamentals (e.g. P/E, market cap). Used in reports and can influence signal context; off saves a bit of collection time.
When on, fetches analyst ratings. Shown in the dashboard and can add context to trading signals.

VADER Sentiment

VADER analyzes sentiment from scraped headlines (no paid API). Affects signal conviction and sentiment metrics shown in reports.

Enable to run local VADER sentiment on collected text. Off = no headline sentiment; signals and dashboard will lack this component.
When on, the system scrapes headlines (e.g. Google News, Yahoo) for VADER to analyze. Off = VADER only runs on other collected text.

Technical Analysis

Technical indicators are computed from price history (no extra API). They appear in the dashboard and can influence signal strength.

Turn on to compute technicals from price data. Off = no technical indicators in reports or signal logic.
How many days of price history to use for technicals. Longer = smoother indicators but slower to react; shorter = more responsive but noisier.

FRED Macro

FRED provides macro indicators (VIX, rates, unemployment, inflation, forex). Used for market context in the dashboard and in assessing risk; requires a FRED API key.

Enable to fetch FRED data each run. Off = no macro indicators; dashboard macro section will be empty.
Check which FRED series to fetch. Each adds one API call per run. All feed into the dashboard macro view and market-context display.

ApeWisdom / OpenInsider

ApeWisdom and OpenInsider supply social/insider activity. Insider data boosts conviction scores and can trigger insider-cluster signals; more tickers/value = more coverage.

Number of top tickers to pull from ApeWisdom. Higher = broader social coverage and potentially more signals; lower = faster runs and less API load.
Only insider trades with total value at or above this amount are counted. Higher = fewer but larger trades (e.g. institutional); lower = more trades including smaller ones.

Paper Trading

Paper trading simulates buys and sells using your signals—no real money. Each run can open/close positions based on conviction and exit rules. These settings control which signals become trades and how positions are sized and closed.

When enabled, the pipeline creates and updates paper positions from signals. Disable to run the pipeline without any paper trades.
Only signals with conviction at or above this value will open a paper trade. Higher = fewer, more selective trades; lower = more trades, including weaker signals.
Nominal dollar size per position (used with conviction-weighted sizing if enabled elsewhere). Affects how much “capital” each paper trade represents.
Cap on how many positions can be open at once. Once reached, no new paper buys until one closes. Limits concentration and simulates limited capital.

Exit Strategy

Paper positions are closed when one of these conditions is met: hold time expires, stop loss hits, or take profit hits. Changing these changes how long positions last and how much gain/loss is locked in.

Positions are auto-closed after this many days if not already closed by stop loss or take profit. Shorter = faster turnover; longer = more time for moves to play out.
Close the position when unrealized loss reaches this percentage (e.g. -10 = close when down 10%). Tighter (e.g. -5) cuts losses sooner; looser allows more drawdown.
Close the position when unrealized gain reaches this percentage. Higher = let winners run longer; lower = lock in profits sooner.
When on, paper trades and P&L are shown in the HTML dashboard. Off = pipeline still runs paper trading but the dashboard does not display it.
On first run (or when needed), paper trading can backfill positions from past signals over this many days. 0 = no backfill; higher = more historical paper positions for comparison with backtests.

Backtesting

Backtesting replays past signals against historical price data to estimate performance. No real or paper trades are placed; results show how the current thresholds and exit rules would have performed. Use the Backtest page to run a backtest; these settings define the simulation parameters.

Starting capital for the backtest. Used to compute returns and final P&L; does not affect which signals are generated, only how performance is scaled.
Base dollar size per simulated position. If conviction-weighted sizing is on, higher-conviction signals use a larger share of this; otherwise each position is this size.
Maximum number of concurrent positions in the backtest. Once reached, no new buys until one closes; limits concentration and mimics limited capital.
When on, position size scales with signal conviction (higher conviction = larger position). When off, every position uses the same base size.

Exit Strategy

Simulated positions are closed when hold time expires, stop loss hits, or take profit hits. Same logic as paper trading; align these with paper settings to compare backtest and paper results.

Positions are closed after this many days if not stopped out or taken profit. Shorter = more turnover; longer = more time for moves to play out.
Close when unrealized loss reaches this percentage. Tighter stops cut losses sooner; looser allows more drawdown.
Close when unrealized gain reaches this percentage. Higher = let winners run; lower = lock in profits sooner.
Only signals with conviction at or above this value are included in the backtest. Higher = fewer, stronger signals; lower = more signals, including weaker ones.

Velocity Spike

Velocity spike signals fire when social or news mention volume jumps sharply. These thresholds control how big the jump must be and how strong the composite score must be for a signal to count.

Minimum percentage increase in mention volume over 24 hours to qualify as a velocity spike. Higher = fewer, stronger spikes; lower = more sensitive, more signals.
Minimum composite score (combining velocity, sentiment, and other factors) for a velocity-spike signal. Higher = only the strongest spikes become signals.

Insider Cluster

Insider-cluster signals fire when multiple insiders trade the same ticker within a lookback window. These settings define what counts as a cluster and how large the activity must be.

Minimum number of distinct insiders who must trade the ticker to form a cluster. Higher = fewer but stronger cluster signals.
Number of days to look back for insider trades. Trades within this window are grouped to detect clusters; longer = more trades considered, potentially more clusters.
Total dollar value of insider activity (buys) in the cluster must meet or exceed this. Higher = only larger, more significant clusters trigger signals.

Reporting

Only signals with conviction at or above this value appear in reports, the dashboard, and are eligible for paper trading and backtest. Higher = fewer, higher-quality signals shown; lower = more signals including weaker ones.

Email

After each pipeline run, a summary report can be sent by email. Configure your SMTP server and recipients here; the report includes top signals and optional charts.

When on, the pipeline sends an email report at the end of each run. Off = no email is sent; dashboard and reports are still generated locally.
Your mail server hostname (e.g. smtp.gmail.com for Gmail). Must support SMTP; use the server your provider documents for sending.
Port for SMTP (587 common for STARTTLS; 465 for SSL). Must match your provider; wrong port will cause send failures.
From address for the report email. Usually the same account you use to authenticate (e.g. your Gmail address).
SMTP password. For Gmail, use an App Password, not your normal login password. Stored in config; keep the file secure.
Who receives the report. Enter one or more addresses separated by commas; all receive the same email.

Report

These options control what appears in the HTML dashboard and in email reports: how many signals to show, whether to include charts, and the size of the velocity watchlist.

Maximum number of top signals to include in the report and dashboard. Higher = more signals shown; lower = only the best few.
When on, the report includes price/sentiment charts for reported signals. Off = text and tables only; faster to generate and smaller emails.
When on, the report includes a watchlist of tickers ranked by velocity/activity (up to watchlist size). Off = only the top signals section.
Number of tickers to show in the velocity watchlist when include watchlist is on. Larger = more tickers; smaller = focus on the top movers.
